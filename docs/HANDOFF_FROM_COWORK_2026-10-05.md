# Cowork → Claude Code 인계 기록 (2026-10-05)

2026-09-16 ~ 10-05 동안 Claude Cowork 세션에서 한 작업의 **결정 이유, 사용자 지시, 교훈**을 옮겨 둔 것이다.
무엇을 했는지(단계·수치)는 `fusion_ready/PIPELINE.md`가 정본이고, 여기는 그 표에 안 들어가는 맥락이다. 자동으로 읽히지 않으니 필요할 때 연다.
지금 상태와 열린 일은 `docs/STATE.md`.

## 1. 작업 방식 — 사용자가 원하는 것

- 다른 기계·Windows에서 할 일은 **그 창에 그대로 붙여 넣을 수 있는 블록**으로 ("한 큐에", "그대로 복붙").
- 큰 결정은 짧은 선택지로 묻고, 사소한 것은 합리적 기본값으로 진행한 뒤 알린다.
- 참고 자료 폴더를 "읽어 보라"고 하면 읽기만 한다(그 폴더에 파일을 남기지 않는다). 다른 프로젝트 자료를 보여주는 건 그 방식을 참고하라는 뜻이지 그 자료를 고치라는 뜻이 아니다.
- 확인하지 않은 것을 확인했다고 하지 않는다. 결과는 한계와 같이 말한다.

## 2. 핵심 결정과 그 이유

**형상 (case 1009, MM-WHS ct_train)**
- 신뢰할 수 있는 건 frame A뿐이었다(원본 메시 16개가 m/mm·프레임 4개가 섞여 있었음). `cardiac_meshes/`는 **좌우 거울상**(X 반사, 비대칭 랜드마크 3/3 위반 — voxel 좌표에서 marching cubes 후 affine 미적용으로 추정). frame A를 "고치지" 말 것.
- 판막이 벽을 뚫던 원인은 크기가 아니라 `generate_valves.py`의 `lv_axis=[0,0,-1]` 하드코딩(실제 축과 ~60°). 파라메트릭 판막은 두께 0 시트였음 → 1.2 mm 솔리드화.
- 유두근 6-DOF 강체 정합은 **불가능** 판정(모든 게이트를 조금씩 동시에 위반) → 원본 CT(0.49 mm)에서 환자 자신의 유두근을 다시 분할하는 쪽으로 감(v4). 이상화 유두근(v3)은 폐기.
- [사용자] "mesh가 너무 rough" → 이진 마스크 marching cubes를 **연속 필드 등위면**으로 교체(19단계, 거칠기 0.19→0.06 mm). v5가 권장 조립.
- [사용자] "관상동맥 모형이 부가가치가 가장 높을 것" → 자체 float32 Frangi + 골격 그래프(18단계). skimage frangi는 3 GB에서 OOM.
- [사용자] "관상동맥이 떠다니는 것 같다" → 그림을 전심장 맥락과 같이 렌더(실제로 붙어 있음, 1 mm 정도 심외막에 묻힘).
- [사용자] "LV 위쪽 원통이 뭐냐" → 단독 LV 모형용 12.5 mm AV-plane 판(34.9 mL)이 전심장 안에서 LA·대동맥 뿌리 자리를 차지한 것 + 판막 구멍을 막던 1 mm 막. 둘 다 제거(26단계).
- [사용자] "half B 내부 경계 불분명·plane 처리 불명확" → `slice_mesh_plane` 뚜껑(귀자르기 부채꼴)을 제약 들로네로 재삼각분할(29단계). 이 과정의 교훈은 §4.
- [사용자] "관상동맥 중 놓친 것 확인" → SCCT 분절표 + 나무 밖 밝은 관 후보 점검(28단계) + 덩어리·정맥 구간 너머에 동맥이 이어지면 얇게 통과시키는 규칙 → LCx 30 → 110 mm.
- 관류 영역은 Voronoi + 고랑 사전정보(20단계). **보이는 혈관 25 mm 밖이 심근의 65 %** — 사전정보 기반이라는 것을 숨기지 않는다. 우세형 가정에 따라 RCA 영역 2–57 g.

**교육용 1차 범위** (`EDUCATION_PACK.md`)
- [사용자] "교육연구용까지 1차로 마치고 그다음 관류 영상" → 1차에서 하지 않는 것: FSI·능동수축, 결절 전기생리, CT-FFR, 임상 주장, 실측 없는 판막 정교화. 2차(관류 영상 검증)는 병원 파트너의 CCTA+SPECT/CMR 쌍이 필요.

**Unreal**
- [사용자] 데스크톱 앱, 에셋 팩 먼저, 그다음 "전부". Blueprint·머티리얼·위젯은 바이너리라 **로직은 C++, 에셋 생성은 에디터 Python** — UE 프로젝트 전체가 텍스트에서 재생성되도록.
- 절단면은 캡 지오메트리 없이 Masked+Two Sided 머티리얼로 — 29단계에서 반절을 수밀로 만든 것이 이 착시의 전제.
- 관류 메시의 정점 색은 정확히 6개 상수(1009에서 5개 출현: LAD 실측 494k / 사전 0, LCx 53k/276k, RCA 19k/657k) — **색 자체가 영역+신뢰도**라 머티리얼이 색 비교만으로 영역을 고른다. `PRIOR_TINT = 0.55·c + 0.45`, uint8 변환은 절삭.
- RAS → glTF: `X=-X_ras, Y=Z_ras, Z=Y_ras`, 행렬식 +1(손방향 보존). 검수: 정면에서 LV가 화면 오른쪽(1009: RV보다 +34 mm).

## 3. PINN 쪽 규칙 (다른 세션에서 확정된 것)

- **합성 데이터 규율**: 합성은 학습 루프가 도는지만 본다. 생리 상수(시정수·저항 등)를 합성 적합도에 맞춰 고치지 않는다. 학습률·반복 수·손실 가중치 같은 수치 공학 선택은 조정해도 된다.
- **Paper B**(`waveform_pinn/`): 5과제·3 출처(eICU+MIMIC-IV, VitalDB, INSPIRE)·2개국. H1(표본 효율) 기각 — 역효과(데이터 적을 때 port 형태가 60분 롤아웃 17/40 발산), H2(임상 증분 가치) 기각(ΔAUROC −0.0029). 진짜 기여 두 가지: ① 매개변수화가 부과보다 중요(P `R=LLᵀ` vs Pm `R=diag softplus`, 같은 보장인데 eICU 적합도 0.629 vs 0.924), ② 보장이 학습된 인공물일 수 있음(E/E2의 "음수 0"은 softplus가 아니라 3.4 L/min 바닥을 만든 자유 affine 덕; E3가 구조적으로 수정). 투고처는 TMLR이 정직한 선택. 2026-08-12 적대적 감사의 결함 6개는 `[AUDIT-n]`으로 표시 — 이 감사 기록이 가장 중요한 자산.
- Paper A의 JBHI 경로는 성능이 아니라 평가 방법론(proxy-label ceiling) 논문으로 재구성하는 것.

## 4. 교훈 (다시 밟지 말 것)

- **좌우 반전은 눈으로 안 잡힌다.** 비대칭 랜드마크(LV vs RV, LA vs RA, 심첨)로 부호를 검사한다.
- **STL은 `process=True`로 읽는다.** 병합 안 한 STL은 모서리를 공유하지 않아 위상 연산이 무의미하다(Triangle은 중복점으로 segfault).
- Triangle: `-Y`는 볼록껍질만 보호, 내부 고리까지 보호하려면 `-YY`. `-p`가 이미 윤곽 안으로 영역을 제한하므로 넘침 채우기 패리티는 기준(알려진 단면 넓이)에 고정해야 한다. 얇은 벽을 스치는 단면에서는 점-다각형 판정이 정의 자체가 모호하다.
- 큰 볼륨: scipy EDT는 ~20 B/voxel → 4천만 voxel 넘으면 2× max-pool 후 EDT(`case_paths.dist_to`). trimesh `closest_point`를 멀리 있는 점에 쓰면 OOM → 정점 cKDTree.
- 관상동맥 가지치기는 voxel 측지거리가 아니라 **나무 거리**로. 골격 → MST를 먼저 하고 가지를 나눈다.
- `CARDIAC_DATA`는 데이터 루트다(형상 스크립트가 한때 ct_train 폴더로 읽던 버그를 `resolve_mmwhs()`로 수정; 예전 방식도 받아 줌).
- mktemp가 실패하면 `unzip -d ''`가 현재 폴더(= 저장소)에 푼다 — 실제로 리허설에서 40개 파일이 저장소 루트에 떨어졌다.
- 점검기는 자기가 만든 것을 같은 프로세스에서 검사하지 않는다(새 셸에서). git이 CRLF를 정규화하므로 바이트 비교는 줄바꿈을 무시하고 한다.
- 블라인드로 쓴 코드는 실제로 돌려 본다: `gpu_smoke`가 `simulate()`의 버그를 찾았고, 검증기 테스트가 오탐 두 개를, 압축 해제 테스트가 저장소 오염 결함을 찾았다.
